# AI backend (AnthropicClient, AISettings, AIPromptBuilder, EvaluationPrompts, SelectionPrompts)

Implementation gotchas specific to this directory. See the root `CLAUDE.md` for architecture, build/test commands, and cross-cutting conventions. The prompts and their test results: `docs/superpowers/specs/2026-10-07-ai-prompts-design.md`; model selection, the request table and the style guide: `docs/superpowers/specs/2026-10-02-ai-model-selection-design.md`.

## Known gotchas

- **AI feature is gated on API key** — `appState.aiEnabled` returns `false` when `aiSettings` is nil or the API key is empty; the ✦ toolbar button is hidden and AI items are omitted from the right-click context menu in that state. Settings are stored in `~/Library/Application Support/Quill/ai_settings.json` (chmod 600) via `AISettingsStore`. `AppState.aiSettings` is the runtime source of truth; updating it (via `onSaveAISettings` callback in `PreferencesView`) enables the feature without relaunch. Every field added since the first release decodes with `decodeIfPresent`, so an older file still loads.
- **Every request is built by `AnthropicClient.requestBody`, from `CompletionOptions(settings:)`** — never send `thinking: {"type": "disabled"}`: Claude Opus 5.5 and Sonnet 5.5 reject it, and adaptive models get no Off option. Adaptive models send `{"type": "adaptive"}` plus `output_config.effort` for a level; enabled-only models (Claude Haiku 4.5) turn Low/Medium/High into Quill's own `budget_tokens` (2,048 / 8,192 / 16,384), not API levels. An unknown model (no list fetched yet) sends no thinking at all, which every model accepts. `max_tokens` is the base plus the budget or 16,000, capped at the model's own limit. The model list and capabilities come from the Models API and are cached in `AISettings.models`, fetched by Settings and, whenever the key changes and the cache is empty, by `AppState.loadAIModelsIfNeeded` (so launch and onboarding never leave every call on the no-thinking fallback); the default model is the newest `line == "haiku"`, else `claude-haiku-5-5`.
- **Bodies are serialized by `AnthropicClient.orderedJSON`, not `JSONSerialization`** — it writes each JSON schema's `properties` in its `required` order, which is the order Claude fills them in. The fact-check schema depends on it: listing every claim before the `fact_checks` is what made the check thorough.
- **Every new prompt returns JSON through `output_config.format`; web search is always direct; never declare code execution** — JSON replaced the `TITLE:`/`CONTENT:` parsing, so no preamble or code fence can reach the editor. Web search uses the newest version in `AnthropicClient.webSearchVersions` the model accepts (a 400 that quotes the tool type and says "does not match any of the expected tags" moves down the list; the version that worked is saved in `AISettings.webSearchToolByModel`, read and written only through `knownWebSearchTool` / `rememberWebSearchTool`, which ignore and clear entries probed before a newer version was added to the front of the list) and always `allowed_callers: ["direct"]`: dynamic filtering's code crashed in 7 of 8 runs and cost twice as much. The API provisions its own code execution for dynamic filtering, so Quill must not declare a `code_execution` tool. With a schema, `Result.text` is the last response's text only, because a `pause_turn` continuation's earlier responses hold search narration. A schema reply that stops at `max_tokens` can't be parsed, so `run` throws `AnthropicError.cutOff(webSearchTool:)` instead of returning it, and so does any reply whose thinking used the whole budget.
- **Evaluate findings carry an exact `original`; Apply refuses missing or ambiguous text** — `EvaluationPrompts.postText` gives Claude plain text with `## `, `- `, `| … |`, `[Caption] ` and `[Footnote] ` markers, built so each line can be found in the editor's text (`postTextMatchesEditorText` checks it against `Scripts/fixtures/evaluate/`, and the JS suite keeps that fixture equal to the real editor). `window.applyEvaluationFinding` matches case-sensitively and on whole words, exact then typography-normalized, never the loose tier, and returns `missing` or `ambiguous` instead of guessing. A line break reads as a space in the editor's text, as `postText` writes it, and Apply keeps line breaks and footnote markers inside a changed phrase. Footnote bodies live in post meta, so Evaluate appends them with `appendingFootnotes(to:meta:)`.
- **The selection commands send reduced HTML with `L`/`F` stubs** — `beginAIOperation` turns links into `<a id="L1">` and footnote markers into `<sup id="F1"></sup>` so Claude never copies a URL or an ID; `showAIResult` puts them back and unwraps any `<a>` or `<sup>` it didn't hand out, so a link Claude writes is always dropped. Make Longer must keep the author's sentences and add no facts or experiences, and Generate must not invent the author's experience: both rules came from test runs where the softer wording failed.
- **Writing style guide is pre-computed, not resolved at call time** — `AISettings.styleGuide` holds a style guide of about 500 words, generated with the selected model and reasoning when the author saves new sample posts or presses Regenerate. `AIPromptBuilder.reduceSample` keeps each sample's structure (headings, lists, tables, captions, links, emphasis) without attributes, and `styleGuideGenerationPrompt` adds each title and word count. `Scripts/style-guide-probe.py` must match that prompt and reduction: change both together, and rerun the probe (a few cents) when a new Haiku ships. Do NOT go back to resolving `samplePostIDs` at call time.
- **AI generate prompt must name the HTML elements** — `AIPromptBuilder.generatePrompt` lists `<h2>`, `<h3>`, `<p>`, `<ul>`/`<ol>`/`<li>`, `<blockquote>` and the table tags. Vague wording like "HTML paragraphs" made Claude emit only `<p>` and drop headings.
