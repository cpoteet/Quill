# Media views (MediaPickerView, GallerySheet, MediaSidebarSection, MediaDetailView)

Implementation gotchas specific to this directory, split out from the project root `CLAUDE.md` (2026-07-11) to keep the root file lazy-loaded. See the root `CLAUDE.md` for architecture, build/test commands, and cross-cutting conventions.

## Known gotchas

- **A `TextField` inside a `List` row with `.onMove` barely takes focus — the drag gesture claims mouse-down first** — `GallerySheet`'s expandable alt/caption rows hit this: clicks on the fields mostly did nothing, while every automated test stayed green (no SwiftUI harness exists here — this class of bug is only findable by using the app). Fix is `.moveDisabled(expandedIDs.contains(sel.id))` on the row, so a row opts out of reorder exactly while it's being edited. Two things must stay in sync with it: (1) the open-hand hover cursor has to be suppressed on an expanded row *and* over its chevron/X buttons, or the row advertises a drag it will refuse; (2) collapse-to-restore-dragging fires on **hover** of the grip, not on click — `moveDisabled` is read when the row is built, so AppKit has already ruled the drag out at mouse-down, and a click would be spent collapsing rather than dragging.
- **`GallerySheet.toggle(_:)` must clear `expandedIDs` when it deselects, not just when it collapses a row** — `expandedIDs` is keyed by media id and outlives `selected`, so deselecting an expanded image in the grid left its id behind; re-selecting the same image brought the row back already expanded and therefore already `.moveDisabled(true)` (see the `TextField`-vs-drag gotcha above), i.e. silently un-draggable for no visible reason. `toggle` now calls `expandedIDs.remove(media.id)` on the deselect branch. Any future per-row state keyed by media id needs the same treatment — there is no SwiftUI harness here, so this is manual-checklist territory (`docs/testing-plan.md` §7.4).
- **`GallerySheet.selected` is `[GallerySelection]`, not `[WPMedia]`** — each entry carries the media item plus the `alt`/`caption` destined for *this* gallery, seeded from `media.altText`/`media.captionText` and sent as the `alt`/`caption` keys in the insert payload. Edits are block-local and never write back to the media library. `GallerySelection` is `public` because `GallerySheet.init` is public. Alt/caption are insert-time only: an inserted gallery is still a read-only card, so fixing a typo means Code View or re-inserting (see `docs/superpowers/specs/2026-08-13-gallery-image-alt-caption-design.md` for why re-editable galleries were rejected).
- **Gallery `image.url` is the display-size URL, not the full-resolution original — `image.fullUrl` carries the latter** — `GallerySheet`'s Size picker resolves each selected image to a specific size via `WPMedia.sizedURL(for:)` and sends that as `image.url` in the insert-gallery JSON payload; this is correct for `<img src>` but was also being reused for the `linkTo: 'media'` anchor's `href`, so choosing e.g. Size=Thumbnail with Link To=Full Image silently linked to the thumbnail file instead of the original. Fixed by sending a separate `fullUrl: media.sourceURL` field alongside `url`; `galleryBlock`'s `renderHTML` reconstruction path in `editor.html` uses `image.fullUrl || image.url` for the anchor href specifically (falls back to `url` for older/other callers that don't send `fullUrl`). Only affects the reconstruction path (sheet-inserted galleries) — loaded galleries render via `sourceHTML` verbatim and were never affected.
- **Shared upload-from-disk helpers: `pickImageFromDisk()` / `uploadPickedImage(_:credentials:)`** (top-level funcs in `MediaPickerView.swift`) — `MediaPickerView` and `GallerySheet` both offer an inline "Upload" button that opens `NSOpenPanel` and uploads via `WordPressClient.uploadMedia`; this logic is factored into these two shared functions so the two flows can't independently drift. Each view still owns its own state update after upload (`MediaPickerView` inserts into `mediaItems`; `GallerySheet` inserts into `mediaItems` *and* appends to `selected`, so an uploaded image is immediately part of the gallery being built — do not drop the `selected.append` half, that was the point of adding the button to the gallery picker in the first place).
- **`MediaThumbnail`** (in `MediaPickerView.swift`) — shared grid-cell view for both `MediaPickerView` and `GallerySheet`, parameterized by `isSelected: Bool = false` (adds accent-color stroke + checkmark overlay, used by `GallerySheet`) and `size: CGFloat = 90` (`GallerySheet` uses 80). Do not reintroduce a second copy of this view for a future picker — extend the parameters instead.
- **`MediaPickerView` is picker-only** — The `.browser` case and `MediaPickerMode` enum have been removed. `MediaPickerView` is now a sheet-only picker used for inserting images into the editor. The media sidebar (`MediaSidebarSection`) handles browsing. Do not add a `mode:` parameter back.
- **`MediaSidebarSection` always reloads on `.onAppear`** — the `isEmpty` guard was removed; media always reloads when the Media tab appears. This is intentional: `PostEditorView` caches individual `WPMedia` items in `appState.mediaItems` for the image toolbar's size-button feature, so `isEmpty` falsely treated a partial cache as a full load, causing the tab to show only cached items. Do not restore the `isEmpty` guard.
- **`MediaSidebarCell` uses `Color.clear` overlay, not `AsyncImage` directly** — `AsyncImage` participates in SwiftUI layout and reports its natural image dimensions when loaded, which breaks `LazyVGrid` column sizing (wide images span both columns, rows misalign). The fix: use `Color.clear.frame(minWidth: 0, maxWidth: .infinity, minHeight: 80, maxHeight: 80)` as the layout anchor and put `AsyncImage` inside `.overlay { }`. Overlays fill their parent's bounds without affecting layout, so every cell is always column-width × 80pt. Do not switch back to `AsyncImage` as the root view of the cell.
- **`MediaThumbnail` in `MediaPickerView` follows the same `Color.clear` pattern** — uses `Color.clear.frame(minWidth: 0, maxWidth: .infinity, minHeight: 90, maxHeight: 90)` with `AsyncImage` in `.overlay { }`. Grid uses 3 fixed `GridItem(.flexible())` columns with `.contentShape(Rectangle())` on each cell. Do NOT use `GridItem(.adaptive(minimum:))` — adaptive columns give cells widths larger than the fixed thumbnail, so tap targets don't cover the full cell area and taps register on the wrong image.
