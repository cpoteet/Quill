# Sidebar views (SidebarView, PostListRow)

Implementation gotchas specific to this directory, split out from the project root `CLAUDE.md` (2026-07-11) to keep the root file lazy-loaded. See the root `CLAUDE.md` for architecture, build/test commands, and cross-cutting conventions.

## Known gotchas

- **Sidebar post list is a real `List(selection:)` with `.listStyle(.sidebar)`** — converted on the `native-ui` branch (2026-09-19). It was `ScrollView { LazyVStack { ForEach { Button } } }`, which existed only to repaint `NSTableRowView`'s blue selection; the native selection is now the wanted appearance, so that reason is gone. Rows carry `.tag(item)` so the binding resolves, and the empty/loading states ride in `.overlay` because a `List` cannot show them as rows. Do NOT revert to `ScrollView+LazyVStack`.
- **The section picker and search field are AppKit wrappers because SwiftUI cannot place them** — `SidebarSectionPicker` and `SidebarSearchField` replaced a SwiftUI segmented `Picker` and two `.searchable` calls on the `native-ui` branch (2026-09-19). Two hard SwiftUI limits forced it, and both were measured, not assumed. A `.segmented` `Picker` on macOS sizes to its label text and centres itself; `.frame(maxWidth: .infinity)` does not stretch it, so it can never match the search field's width. `.searchable(placement: .sidebar)` is always hoisted to the top of the sidebar column, so nothing can be placed above it — that alone rules out picker-above-search. `NSSegmentedControl` with `segmentDistribution = .fillEqually` fixes both: equal segments and an exact width match. One `SidebarSearchField` now serves both sections, switching binding (`searchText` / `mediaSearchText`) and prompt off `selectedSection`, which is why `MediaSidebarSection` no longer carries its own `.searchable`.
- **`NSSegmentedControl` height is fixed by AppKit — `controlSize` and SwiftUI frames both do nothing** — `controlSize = .large` leaves it at 24pt, and a `.frame(height:)` or a `sizeThatFits` reporting 30pt just centres a 24pt control inside a taller box, adding dead space rather than height. The bezel draws at its own fixed height. Do not retry either; a taller nav control needs a custom SwiftUI segmented control, which is a deliberate trade (it stops inheriting system styling). Spacing between the picker and the search field is the only lever, and it lives in the `VStack(spacing:)` in `SidebarView.body`.
- **`ClickToFocusSearchField` refuses first responder until clicked, and that guard is load-bearing** — AppKit hands first responder to the only focusable control in a SwiftUI window, so a plain `NSSearchField` grabs focus on launch and then never gives it up: SwiftUI `List` rows do not claim first responder when clicked and `NSSegmentedControl` never does by design, so nothing takes it back. The subclass overrides `acceptsFirstResponder` to return false until its own `mouseDown` fires. Do NOT "fix" launch focus with `window.makeFirstResponder(nil)` from `viewDidMoveToWindow` instead — that was tried and it silently blocks click-to-focus afterwards. `SidebarView.releaseSearchFocus()` handles the other half, clearing focus on `selectedItem` / `selectedSection` change. Verify any change here with real `CGEvent` clicks — see the scripted-clicks gotcha in `docs/gotchas.md`.
- **Taxonomy cache `clearAll()` is gated on site URL change** — `SidebarView.loadAllSections()` compares a stored `UserDefaults` site URL before calling `clearAll()`. Normal launches serve from the 24-hour SQLite cache; only a site URL change triggers a fresh fetch. Do NOT call `clearAll()` unconditionally — it defeats the cache on every launch.
- **`.task(id:)` reruns on every view remount, not just id changes** — `SidebarView` is conditionally included in `ContentView`'s hierarchy (`if appState.isSidebarVisible`), so hiding/showing it remounts the view and reruns every `.task`/`.task(id:)`, even when the id is unchanged. `AppState.lastLoadedCredentials`/`hasCheckedForUpdate` guard `loadAllSections()`/`UpdateChecker.check()` from re-running on every toggle. Both are set only on a *successful* completion (not on failure): `lastLoadedCredentials` is set after a successful `loadAllSections()`, and `hasCheckedForUpdate` is set only inside the `do` branch after `UpdateChecker.check()` returns without throwing — `UpdateChecker.check() throws` specifically so a transport/decode failure (vs. "checked fine, no update found") can be told apart and left to retry on the next remount instead of being silently skipped for the rest of the session.
- **Delete state in SidebarView** — `itemPendingDelete: PostItem?` drives the confirmation alert; `deleteError: String?` drives the error alert. Both are `@State` locals in `SidebarView`. Setting `itemPendingDelete` non-nil triggers the alert; the confirm button clears it and calls `performDelete` in a `Task`.
- **Media sidebar when Media tab active** — `SidebarView` swaps the post list for `MediaSidebarSection()` when `selectedSection == .media`. Do not remove that `else` branch or replace it with `Spacer()`. Since 2026-09-19 the section picker and search field sit *above* that branch in the `VStack`, so both stay visible in Media mode — the picker must, because it is the only way back out, and the search field retargets to `mediaSearchText` with a "Search Media" prompt. Earlier wording said search was hidden here; that stopped being true when the two `.searchable` calls became one shared field.
- **`UpdateChecker` runs once on launch via `.task` in `SidebarView`** — fetches `version.json` from GitHub Pages, compares with `CFBundleShortVersionString`, and sets `appState.updateAvailable` if newer. `dismiss()` saves the version to `UserDefaults` so it won't reappear. The ephemeral `URLSession` is invalidated after use via `defer { session.invalidateAndCancel() }`.
