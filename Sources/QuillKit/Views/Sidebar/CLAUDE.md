# Sidebar views (SidebarView, PostListRow)

Implementation gotchas specific to this directory, split out from the project root `CLAUDE.md` (2026-07-11) to keep the root file lazy-loaded. See the root `CLAUDE.md` for architecture, build/test commands, and cross-cutting conventions.

## Known gotchas

- **Sidebar post list is `ScrollView+LazyVStack`, NOT `List`** — SwiftUI's `List` on macOS uses `NSTableRowView` which paints selection blue at the AppKit layer, overriding any SwiftUI modifier. `SidebarView` uses `ScrollView { LazyVStack { ForEach { Button } } }` for full control over selection appearance. Do NOT revert to `List` with a selection binding.
- **Taxonomy cache `clearAll()` is gated on site URL change** — `SidebarView.loadAllSections()` compares a stored `UserDefaults` site URL before calling `clearAll()`. Normal launches serve from the 24-hour SQLite cache; only a site URL change triggers a fresh fetch. Do NOT call `clearAll()` unconditionally — it defeats the cache on every launch.
- **`.task(id:)` reruns on every view remount, not just id changes** — `SidebarView` is conditionally included in `ContentView`'s hierarchy (`if appState.isSidebarVisible`), so hiding/showing it remounts the view and reruns every `.task`/`.task(id:)`, even when the id is unchanged. `AppState.lastLoadedCredentials`/`hasCheckedForUpdate` guard `loadAllSections()`/`UpdateChecker.check()` from re-running on every toggle. Both are set only on a *successful* completion (not on failure): `lastLoadedCredentials` is set after a successful `loadAllSections()`, and `hasCheckedForUpdate` is set only inside the `do` branch after `UpdateChecker.check()` returns without throwing — `UpdateChecker.check() throws` specifically so a transport/decode failure (vs. "checked fine, no update found") can be told apart and left to retry on the next remount instead of being silently skipped for the rest of the session.
- **Delete state in SidebarView** — `itemPendingDelete: PostItem?` drives the confirmation alert; `deleteError: String?` drives the error alert. Both are `@State` locals in `SidebarView`. Setting `itemPendingDelete` non-nil triggers the alert; the confirm button clears it and calls `performDelete` in a `Task`.
- **Media sidebar when Media tab active** — `SidebarView` hides the post list / search / toolbar when `selectedSection == .media`. The `else { MediaSidebarSection() }` branch fills the sidebar with the thumbnail grid. Do not remove that `else` branch or replace it with `Spacer()`.
- **`UpdateChecker` runs once on launch via `.task` in `SidebarView`** — fetches `version.json` from GitHub Pages, compares with `CFBundleShortVersionString`, and sets `appState.updateAvailable` if newer. `dismiss()` saves the version to `UserDefaults` so it won't reappear. The ephemeral `URLSession` is invalidated after use via `defer { session.invalidateAndCancel() }`.
