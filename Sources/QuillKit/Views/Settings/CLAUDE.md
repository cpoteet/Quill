# Settings views (PreferencesView, PostSettingsPanel)

Implementation gotchas specific to this directory, split out from the project root `CLAUDE.md` (2026-07-11) to keep the root file lazy-loaded. See the root `CLAUDE.md` for architecture, build/test commands, and cross-cutting conventions.

## Known gotchas

- **Page-specific settings panel** — `PostSettingsPanel` takes `postType: String` and `pages: [WPPost]`. When `postType == "page"` it shows Parent Page picker + Slug + Discussion (no categories, tags, or excerpt). Posts show categories, tags, slug, excerpt, and discussion. The `isPage` computed var drives all conditional rendering.
- **Style guide regeneration rules in `PreferencesView.saveAll()`** — the guide is regenerated only when: (a) sample post IDs have changed, or (b) no guide exists yet. If IDs are unchanged and a guide already exists, the existing guide is reused and no Claude call is made. If the WordPress site URL changes, `aiSamplePostIDs` is cleared and the guide is set to `nil` — post IDs from one site are meaningless on another. `saveAll()` is `async`; the button is disabled via `isAnalyzing` while the Claude call is in flight.
- **`PreferencesView` must not use `@EnvironmentObject`** — the SwiftUI `Settings` scene creates a separate window context that does not inherit the main app's environment objects. `PreferencesView` receives what it needs as explicit init parameters: `posts: [WPPost]` (for the sample post picker) and `onSaveAISettings: ((AISettings) -> Void)?` (to update `AppState` after saving). The `Settings` scene passes these from `appState` at the call site where `AppState` is in scope.
- **Preferences has exactly one front door: the `Settings` scene under ⌘,** — `QuillApp` also presented `PreferencesView` as a modal sheet, so the same UI had two chromes and two dismissal behaviours. The sheet and the `AppState.isShowingPreferences` flag were removed on 2026-09-19. Everything that needs to open preferences reads `@Environment(\.openSettings)` and calls it: `ContentView.loadCredentialsAtLaunch()` when no credentials exist, plus the "Open Blog Settings" buttons in `SidebarView` and `MediaSidebarSection`. Do not add a second presentation path.
- **The launch credential load lives in `ContentView`, not `QuillApp`** — it moved there because `@Environment(\.openSettings)` can only be read inside a `View`, and the no-credentials branch has to open the Settings window. `QuillApp`'s scene body cannot read it.
- **`PreferencesView` keeps an explicit Save button on purpose** — macOS settings normally apply as you type, but this Save runs a live credential check against the WordPress site and can then regenerate the AI style guide. Applying per keystroke would fire a network call per character. Do not "fix" this to auto-apply.
- **`PostSettingsPanel` is a `VStack` of sections, not a `Form`** — it already uses real `Picker`, `DatePicker`, `Toggle(.switch)` and `Toggle(.checkbox)` controls. `.formStyle(.grouped)` belongs in the Settings window; Apple's own inspectors use this ungrouped shape. The panel also must not set its own width — see `docs/gotchas.md`.
- **`PostSettingsPanel` must not sort, and its two taxonomy lists must stay `LazyVStack`** — `AppState` hands it pre-ordered `categories` and `tags` (see `docs/gotchas.md`); the panel's `filter`s preserve that order, so `filteredCategories`, `filteredUnselectedTags` and `selectedTagNames` deliberately contain no `sorted`. Reintroducing a sort in a computed property, or reverting either nested list to a plain `VStack`, brings back the main-thread stall that fades the toolbar on every inspector open.
