# App layer (AppState, QuillApp, UpdateChecker)

Implementation gotchas specific to this directory. See the root `CLAUDE.md` for architecture, build/test commands, and cross-cutting conventions.

## Known gotchas

- **`appState.posts` / `appState.pages` have empty `content` and `excerpt`** — `fetchAllPaginated` sends a `_fields` filter so post bodies are not downloaded at startup. `WPPost.content` is always empty in the list cache. `PostEditorView.loadItem()` fetches the full individual post on open and applies it via `applyRemotePost`. Do NOT read `post.content.rendered` from list items; always fetch the individual post first.
- **Media state lives in `AppState`** — `appState.mediaItems`, `appState.selectedMedia`, `appState.isLoadingMedia`, `appState.hasLoadedMedia`, `appState.mediaError` are the single source of truth. `MediaLibraryView` loads into and reads from these; `ContentView`/`MediaDetailView` observe `selectedMedia` to show the detail view. Pagination state is local to the loading view — `hasMore` in `MediaLibraryView`, whose next request derives its offset from `mediaItems.count` rather than a stored page cursor.
- **Loading state uses `isLoading*` + `hasLoaded*` pairs** — `isLoadingList`/`hasLoadedList` and `isLoadingMedia`/`hasLoadedMedia` work together. Both `isLoading*` default to `true` and `hasLoaded*` default to `false` so views show a spinner (not the empty state) before the first fetch completes. Guard-returns on nil credentials must set both flags (`isLoading* = false`, `hasLoaded* = true`) to avoid stuck spinners. `CancellationError` branches intentionally do NOT set `hasLoaded* = true` — the cancelled task is expected to be followed by a replacement task. The media branch (`MediaLibraryView.loadMedia`) also leaves `isLoadingMedia` alone, because the replacing load owns it: clearing it there showed the empty state for a moment on a filter switch, before the replacement's request had returned. The list loads in `SidebarView` still set `isLoadingList = false` on cancellation.
- **`NSAllowsArbitraryLoadsInWebContent` in Info.plist** — allows WKWebView to load HTTP images from old posts that predate HTTPS migration. Does NOT affect URLSession API calls (those still enforce ATS). Do not remove this — old posts may reference `http://` image URLs.
- **`NSWindow.allowsAutomaticWindowTabbing = false` in `QuillApp.init()`** — macOS automatically injects a "View → Show Tab Bar" menu item and window-tabbing support into every NSWindow-based app. Since Quill is a single-window app, this is noise. The class-level property is set to `false` in `QuillApp.init()` to suppress it. Do not remove this — the menu item reappears without it.
- **The main `WindowGroup` keeps `id: "main"`** — without an id, SwiftUI's frame autosave key embeds a SwiftUI address that changes on every boot, so the window position was lost after each reboot and a stale `NSWindow Frame SwiftUI.WindowGroup<…>` key piled up per boot. With the id the key is `NSWindow Frame main-AppWindow-1`, and the sidebar's split-view key became `main-AppWindow-1, SidebarNavigationSplitView`, which let `ContentView` drop its own sidebar-width save. Verified across a reboot on 2026-10-25: window and sidebar came back unchanged and no new `SwiftUI.WindowGroup<…>` key was written. See `docs/platform-workarounds.md`.
- **`showAboutWindow()` sizes the window before `center()`** — `NSWindow(contentViewController:)` starts as a 1×32 titlebar strip and the hosting controller sizes it only later, growing it from its origin. `center()` on the strip left the About window's left edge at mid-screen and its top against the menu bar. `setContentSize(hosting.view.fittingSize)` first gives `center()` the real 400×492 frame. Verified 2026-10-25: opens at x=535 on a 1470pt screen, every launch.
- **File menu commands use `AppState.createNewDraft(type:draftStore:)` and `AppState.triggerMediaUpload`** — `QuillApp.commands` cannot use `@EnvironmentObject`, but `appState` and `appServices` are `@StateObject` properties captured by reference in the commands closure. New Post / New Page call `appState.createNewDraft(type:draftStore:)` directly. New Media sets `appState.triggerMediaUpload = true` after switching to `.media` section; `MediaSidebarSection` watches this in both `.onAppear` (if the view wasn't yet mounted when the flag was set) and `.onChange` (if already mounted), then calls `uploadFromDisk()` and resets the flag to `false`. Do not collapse these into a single observer — both are needed to handle the mount-ordering race.
- **Switching sites goes through `AppState.connect`, never a bare `credentials =`** — when the site key changes, `connect` awaits `persistOpenPost` (the open editor's flush, also used on quit) while the old credentials are still set, then clears the selection, `posts`, `pages`, `mediaItems` and `selectedMedia` before setting the new credentials. Autosave stashes are keyed by `Credentials.siteKey` and post ID; `PostEditorView` keys a post's stash by `loadedSite`, the site it was loaded from, so the teardown flush after a switch still lands under the old site. Rows from before the site key have site `''` and are claimed by the first site that loads its lists (`AutosaveStore.adoptUnsited`, called from `SidebarView.loadAllSections`). Local drafts are not tied to a site: they show for every site and publish to the current one.
