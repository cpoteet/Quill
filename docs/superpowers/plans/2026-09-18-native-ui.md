# Native macOS UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Quill's hand-built window chrome, warm panel surfaces and hand-rolled split layout with native macOS 27 structure, keeping the app's identity in the amber accent colour rather than in painted surfaces.

**Architecture:** `NavigationSplitView` with a system-drawn sidebar `List`, a real window toolbar carrying every action, and a real `.inspector` for the two right-hand panels. Roughly 250 lines of chrome workarounds are deleted and nothing replaces them. The app takes the user's system accent for selection, focus rings and the Publish button — see Task 7.5, which reversed the original amber-accent decision.

**Tech Stack:** Swift 6.4, SwiftUI (macOS 27), SwiftPM, WKWebView, Swift Testing, node/jsdom.

**Spec:** `docs/superpowers/specs/2026-09-18-native-ui-design.md`

## Global Constraints

- **Branch:** all work happens on `native-ui`. Never commit to `main`.
- **Deployment target:** macOS 27.0 exactly. No `if #available` gates anywhere.
- **Build after every task:** `osascript -e 'quit app "Quill"' 2>&1; sleep 2 && ./build.sh 2>&1 && open Quill.app`. Skipping the quit leaves the old binary running and shows no visible change.
- **Never test edits on a published post or page.** Click "+ New Post", test on that local draft, discard it when done. One ⌘Z too many past the test edits undoes the initial content load and empties the editor.
- **Amber is gone.** The original plan kept `Color.wpAmber` and made it the app accent. Task 7.5 deleted it: the app now uses the user's system accent, and the only surviving use of the old hue is a file-private `draftAmber` inside `statusColor(_:)`. Every other `wp*` colour token is deleted.
- **No new files under `Sources/QuillKit/Resources/`.** `build.sh` copies resources by name, one `cp` line each; a new resource without its own line 404s at runtime while every test still passes.
- **Comments:** default to none. This codebase's existing comments explain non-obvious *why*; when you delete the code a comment explains, delete the comment. Do not add narration comments like "converted to NavigationSplitView".
- **Do not commit unless the plan step says to.** Each task ends with exactly one commit.

## Why this plan is not TDD

This is a view-layer refactor. Quill's 428 Swift tests cover models, storage,
API and helpers; none of them render a view, and no test can assert "the title
bar is system-drawn" or "the sidebar selection is amber". Writing view tests
solely to satisfy a TDD shape would be test theatre.

The cycle used instead, every task:

1. `swift build 2>&1 | tail -20` — must be clean.
2. `./build.sh && open Quill.app` — plus the named visual check for that task.
3. `./test.sh` — regression guard, at the milestones that name it.

Two real test obligations do exist and are honoured:

- `AppStateTests` asserts `SidebarSection.icon` and `.shortTitle` for all four
  cases. The toolbar picker consumes `shortTitle`, so those tests must keep
  passing untouched — they are the contract for Task 4.
- The webview colour change in Task 8 must not alter markup, so the 1,202 JS
  tests and `--check-fixtures` are the gate there.


```swift

```

This is a suppression, not a fix. It is correct only because the write happens
once, in test setup, ahead of any task. If that ever stops being true, this
needs a real lock.

- [x] **Step 4: Put LinkPickerModel on the main actor**

`LinkPickerModel` is an `ObservableObject` that mutates `@Published` properties
from inside a detached `Task`, hopping back via `MainActor.run`. Under Swift 6
that produces three errors at lines 40, 43 and 47. Isolating the whole class
removes the need for the hops.

Add the attribute:

```swift

```

Then, inside `scheduleSearch`, replace:

```swift

            let found = (try? await onSearch(text)) ?? []
            guard !Task.isCancelled else { return }
            await MainActor.run {
                self.results = found
                self.isSearching = false
            }
```

with:

```swift

            let found = (try? await onSearch(text)) ?? []
            guard !Task.isCancelled else { return }

            isSearching = false
```

- [x] **Step 4a: Make the isolated-by-inheritance statics nonisolated**

This is the part no compiler error warns you about. SwiftUI's `View` and
WebKit's `WKNavigationDelegate` are `@MainActor` under Swift 6, so every static
member of a conforming type inherits main-actor isolation whether it needs it or
not. Both protocols are `@preconcurrency`, so calls from nonisolated test code
still **compile** — and then trap at runtime, killing the test process with no
per-test failure reported.

Nine pure static helpers are affected. Mark each `nonisolated`:

In `EditorCoordinator.swift`: `mediaSizesDict(for:)`, `isAllowedExternalURL(_:)`.

In `PostEditorView.swift`: `nextAlarm(from:names:)`, `uploadStatusText(index:total:)`,
`uploadSuccessMessage(inserted:didConvert:)`,
`uploadFailureMessage(failed:total:firstError:)`, `previewURL(from:)`,
`publishButtonTitle(status:isPublishedRemote:)`, `toastMessage(forStatus:)`.

`BlockRiskAlarm.displayName(for:)` does **not** need it — `BlockRiskAlarm` is a
plain struct, not a `View`.

Two mock URLProtocol handlers in `Tests/QuillTests/Support/` also need
`nonisolated(unsafe)`, for the same reason as `AppSupportDirectory.override`:
`MockURLProtocol.requestHandler` and `AnthropicMockURLProtocol.requestHandler`.

**Symptom to recognise.** If the suite dies with "Some test targets reported
failures" while every test prints "started" and none prints "passed", the test
process crashed rather than failed. Re-run with `swift test --no-parallel`; the
last test to print "started" is the one that trapped.

### Task 7.5: Drop the custom accent and let the system accent win

**Superseded the original Task 7.5 mid-execution.** The original task darkened
`wpAmber` from `#EBA32A` to `#B45309` so it would survive macOS's prominent and
disabled button rendering. That was implemented and rejected on sight: the
darker amber read as brown. The rejection prompted a better question — why keep
a custom accent at all?

**The decision: delete the app accent entirely.** The app follows the user's
System Settings accent, like a standard Mac app.

The argument that settled it: `NSAccentColorName` only wins while the user's
System Settings accent is "Multicolour". Anyone who has picked an accent never
saw Quill's amber. So the spec's central claim — that Quill's identity lives in
the accent colour — was already false for a large share of users. It was not an
identity, it was a default. And every contrast defect the original Task 7.5
existed to fix came from forcing a hand-picked colour through renderings Apple
tunes for its own accents. Adopting the system accent removes that whole class
of bug permanently rather than re-deriving contrast each time something looks
wrong.
