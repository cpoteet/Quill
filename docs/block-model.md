# Quill — the Gutenberg block model

How Quill models, carries and preserves Gutenberg blocks. Referenced from the root `CLAUDE.md`.

- **Adding a block setting is one line in `block-settings.js`** — the registry names how each Gutenberg setting draws (`carried`, `flagClass`, `valueClass`, `style`, `attr`), and the machinery derives the Tiptap attribute (`withBlockSettings` in `editor.html`), the delimiter key (`attrsFromSettings`/`ownedAttrsFor` in `block-descriptors.js`) and the toolbar control (`_buildSettingControl`) from it. A `control` field adds the toolbar control; `propagate: '<node>'` also writes the value to every descendant of that type in the same transaction, which is what core's twice-stored accordion icon settings need. Never write a `sourced` setting to the delimiter — WordPress reads those back out of the markup. Two settings the registry cannot express are document structure, not settings, and stay hand-written: a table's `<thead>`/`<tfoot>` sections (`tableRow.rowType`) and its caption's attachment to the figure.
- **An attribute no block setting names is carried anyway** — every node wrapped by `withBlockAttrs` snapshots its element's attributes on load (`withRawAttrs` in `editor.html`) and replays them on save in the source's own order, with the node's own values winning. That is what keeps columns' `is-not-stacked-on-mobile`, a details `name` and an ordered list's `reversed` after an edit, none of which has a registry entry. Two lists bound it: `RAW_ATTRS_MODELED` names the attributes a node draws itself, which must never be replayed or a value the user just turned off comes back — a node whose class any setting writes lists `class` there; `RAW_ATTRS_EXEMPT` holds the four figure blocks, which rebuild their figure from modelled attributes instead. A setting that draws a *child element* still needs a registry entry.
- **Unsupported block preservation — one path, not two** — on load, `window.setContent` (and `_exitCodeView`'s user-edited branch) run `post_content` through `wrapUnsupportedBlocks`, which uses Quill's `parseBlocks` (`block-parser.js`) to enumerate top-level blocks, cuts each one's source by offset, and replaces **every block Quill has no node for** with a `div.wp-block-quill-unsupported` carrying its exact source; `toWordPressHTML` swaps each wrapper back for those bytes verbatim on save. The rule is simply `!!blockName && !modelsBlockName(blockName)`, plus a guard that a modeled name saving no markup is wrapped too. Covers Group, Cover, Media & Text, Spacer, Custom HTML, shortcodes, the self-closing dynamic blocks, page breaks, Read More, and any third-party block. The class-based `gutenbergPassthrough` card is what is left of the old path: it now only holds an unmodeled block *nested inside* a modeled container, where there is no top-level slice to wrap. `_reportBlocksAtRisk` separately counts every block name in the source tree — at every depth, per instance — against the same count taken from the document, and posts `blocksAtRisk` to Swift, which shows `BlockRiskAlarm`'s banner and refuses to save (and suspends autosave) until acknowledged. Spec: `docs/superpowers/specs/2026-09-12-unsupported-block-preservation-design.md`.
- **`parseBlocks` is held to WordPress's parser, not to the spec** — `block-parser.js` is Quill's own reader of block comments (written without WordPress's GPL source); `Scripts/test-block-parser.js` compares its tree with `@wordpress/block-serialization-default-parser`, a test-only dependency, and that comparison is the authority. Design: `docs/superpowers/specs/2026-09-25-block-parser-rewrite-design.md`. Four rules were measured against WordPress after the spec was written and are not in it: a stray closing comment at the top level starts a freeform block at the end of the previous block, so top-level text before it joins that block; a closing comment ending in `/-->` is self-closing; a *nested* block closed with nothing since its last inner token records `""` in `innerContent` (a top-level one records nothing); and the attribute text is JSON-parsed together with the whitespace after `}`, so a no-break space, form feed or U+2028 there gives `attrs: null`. The one deliberate difference: two or more blocks open at the end of the input nest instead of repeating the inner text, and `blockSourceSlices` appends their missing closing comments.
- `gutenbergPassthrough` Tiptap node (`editor.html`) — two parse rules feed it. `div.wp-block-quill-unsupported` is the wrapper every unmodeled *top-level* block now arrives in, and is byte-exact. The `[class*="wp-block-"]` catch-all is the fallback for an unmodeled block *nested inside* a modeled container; it preserves `outerHTML` but not inter-element whitespace, because Tiptap strips that before any parse rule runs. Both render the same static "Not editable in the visual editor" card. See `docs/superpowers/specs/2026-07-12-gutenberg-passthrough-block-design.md` and the `toWordPressHTML` gotcha above about its shielding window.
