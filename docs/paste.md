# Paste

How HTML from the clipboard becomes Gutenberg markup, and why each step exists. The code is `cleanPastedHTML` and its helpers in `Sources/QuillKit/Resources/editor-transforms.js`, called from `transformPastedHTML` in `editor.html`. Tests: `Scripts/test-editor-paste.js` and `Scripts/test-editor-paste-sources.js`. The captures in `Scripts/fixtures/paste/` are the regression corpus.

## The two kinds of paste

**A copy made inside Quill** carries ProseMirror's `data-pm-slice` marker on its first element. Its HTML is Quill's own render, so it is left exactly as it is. The marker alone does not identify it: every ProseMirror or Tiptap app writes the marker (Confluence, Substack, GitLab), and WebKit keeps it. editor.html therefore remembers the plain text of Quill's last copy or cut (`_rememberCopy`), and `_classifyPaste` calls a paste Quill's own only when its HTML carries the marker **and** its `text/plain` matches that text, ignoring whitespace differences. `transformPastedHTML` reads the result once and clears it. A copy made before a relaunch is not remembered, so it is treated as an outside paste and cleaned.

The copy, cut and paste listeners are on `document` in the capture phase. In real WebKit ProseMirror's paste handler on the editor element ran before a listener on that element, and ProseMirror's cut has emptied the selection by the time its handlers finish. jsdom shows neither.

`cleanPastedHTML` and `pastedBlocksAsListItems` do not check the marker themselves, so anything that reaches them is cleaned. That includes Paste as Markdown, whose raw HTML is always cleaned.

ProseMirror reads the marker *after* `transformPastedHTML` returns, to rebuild how the slice was opened, so the marker must never be stripped in the hook. It is dropped where it would be saved instead: `isCarryableAttr` refuses it, and `sourceHTMLOf` removes it from the verbatim `sourceHTML` that galleries, embeds and passthrough blocks keep.

**Anything else** is reduced to what Quill models. Every source leaves attributes Gutenberg's `save()` would not write, and the raw-attribute carrier (`docs/block-model.md`) would otherwise save them all. Gutenberg then reports the block as invalid. Before this cleanup existed, 14 of 21 sampled outside pastes saved invalid blocks.

## What WebKit hands the editor

WKWebView sanitizes HTML from other apps and websites before the page sees it. It re-renders the markup and writes each element's computed style inline: 15 to 18 properties per element (`orphans`, `widows`, `caret-color`, `-webkit-text-stroke-width`, ...). It also strips HTML comments, so a copy from the block editor arrives without its `<!-- wp: -->` delimiters. It keeps Word's `@list` definitions in a `<style class="WebKit-mso-list-quirks-style">`. A jsdom test cannot reproduce any of this. That is why the fixtures in `Scripts/fixtures/paste/` are captures of what WebKit delivered, not what the source app wrote.

## The steps, in order

Order matters: anything that reads a style runs before the styles are stripped.

1. **Remove chrome.** Scripts, styles, form controls, SVG, and visually hidden text (`screen-reader-text`, `visually-hidden`, `sr-only`) are removed. So are elements hidden with `display:none` or Word's `mso-hide`, and every comment except block delimiters. Incoming `data-quill-*` attributes are removed so a page cannot hand Quill delimiter JSON. `aria-hidden` content is **kept**: it is hidden from screen readers, not from the eye. Removing it lost visible link text on developer.wordpress.org and card titles on Apple's site.
2. **Buttons.** A button whose text, `aria-label` or `title` mentions copy or clipboard is chat-app or docs chrome and is removed. Any other button is unwrapped, because its label can be content (MDN's compatibility table puts version numbers in buttons).
3. **Images Quill cannot hold.** An image in a table cell or list item becomes its alt text; core's cells and list items hold text, not image blocks. An image whose source the page cannot read (`file:`, `cid:`) is removed. `data:` and `blob:` images stay: they are uploaded after the paste (see below).
4. **Wrappers.** Google Docs' `<b id="docs-internal-guid-…" style="font-weight:normal">` wraps the whole selection and must be unwrapped before styles become tags, or everything turns bold. Word's bookmarks (`<a name>`), footnote and comment anchors, `<o:p>` and VML are removed or unwrapped. WebKit wraps a selection holding an open `<details>` in a second `<details>` with no summary, and that wrapper is unwrapped. A plain `<details>` becomes core/details. An inline `<cite>` is unwrapped, because Quill's `cite` node is a quote's citation block and parsing an inline one as a block splits the list item it sits in.
5. **Word lists.** Word writes one paragraph per item, with `mso-list:lN levelM` in its style and the marker in a `span[style*="mso-list:Ignore"]`. The `@list lN:levelM` rule's `mso-level-number-format` says bullet or numbered. Consecutive items become nested `<ul>`/`<ol>`. A lettered or roman level gets `list-style-type` plus a `{"ordered":true,"type":"lower-alpha"}` delimiter, as core writes it. A numbered list that starts above 1 keeps its `start`.
6. **Code.** Code copied from an editor (VS Code) is a `div` with `white-space: pre` and a monospace font, with one child div per line. It becomes a `<pre><code>` of the text with line breaks. Every `<pre>` is reduced to one `<code>` holding only its text. That drops the language label and copy button ChatGPT draws inside the `pre`, and keeps a `language-*` class. A language label just above the block (Claude.ai) is removed when its text matches the language. A monospace `<span>` in prose becomes inline `<code>`.
7. **Media.** A YouTube, Vimeo or Spotify `<iframe>` becomes Quill's embed figure with the page URL WordPress embeds from. Any other iframe is removed. `<video>` and `<audio>` become core/video and core/audio, with delimiters so the passthrough keeps them as blocks. WordPress emoji images (`img.emoji`) become the emoji character.
8. **Styles to tags.** On `span` and `font`: bold weights become `<strong>`, italic becomes `<em>`, line-through becomes `<s>`, underline becomes `<u>` (not inside a link, whose underline is decoration), and `vertical-align` becomes `<sup>`/`<sub>`. A `<b>`/`<strong>` explicitly set to normal weight is unwrapped.
9. **Alignment.** A paragraph or heading centered or right-aligned by `text-align`, `align` or a `has-text-align-*` class gets core's `{"style":{"typography":{"textAlign":…}}}` delimiter and class. That is what WordPress 7.1's own paste handler produces. A cell's alignment, from the cell or from the one paragraph inside it (Word), becomes `has-text-align-*` plus `data-align`, with `scope`/spans moved after them into core's attribute order.
10. **Cells hold text.** Blocks inside a table cell become lines separated by `<br>`, innermost cells first so a nested table collapses into its rows.
11. **Preset classes.** On paragraphs, headings, lists and quotes, `has-X-color`, `has-X-background-color`, `has-X-font-size`, `has-X-font-family` and `has-X-gradient-background` become the delimiter attributes core draws them from, in core's key order. Without that, WordPress keeps them as a custom `className`.
12. **Attributes and classes.** Each element keeps only the attributes in `PASTE_KEEP_ATTRS`. A style survives only on an inline-colour `<mark>`, rebuilt in core's shape, and on a list whose type step 5 set. Classes survive when Quill models them (`PASTE_KEEP_CLASS`) and the front end did not add them at render (`PASTE_RENDER_CLASS`: `is-layout-*`, `wp-container-*`, `wp-block-paragraph`, ...). An `id` survives on headings (core's anchor), footnote entries and footnote marker links only.
13. **Structure.** Bare spans are unwrapped, and a link around blocks (a card) is pushed into each innermost block. Custom elements (a hyphen in the tag) are unwrapped. A `div` or sectioning element becomes a paragraph when it holds only inline content, and is unwrapped otherwise. Images are lifted out of paragraphs so the parser does not leave an empty paragraph where it split one. Empty paragraphs and headings, and whitespace or `<br>` between blocks, are removed. Whitespace between inline runs is kept: it is a word space.

## Around the cleanup

- **Pasting into a list item:** `pastedBlocksAsListItems` turns the pasted blocks into further items, as the block editor does. Left alone, ProseMirror packs them into one `<li>` as paragraphs. A single pasted paragraph joins the item instead. A quote becomes items too, whether pasted alone or with other blocks: its paragraphs, citation, bare text, headings and nested lists each become an item. A quote holding anything else is left as one item.
- **Pasting blocks into an empty paragraph:** `transformPasted` in `editor.html` closes the start of the slice when the cursor is in an empty top-level paragraph and the first pasted node is a text block. The first block replaces the paragraph and keeps its own attributes (a centred heading stays centred), as in the block editor. Pasted into a paragraph with text, the first block still joins it.
- **A lone URL** pasted into an empty top-level paragraph becomes an embed when `detectEmbedProvider` knows the host (`handlePaste`). In a sentence it stays a link.
- **WebKit's `<details>` bug:** when a selection copied from a web page holds a closed `<details>`, WebKit's HTML flavor is just the empty `<details>`, while the plain text is whole. When the HTML contains `<details>` and its parsed text is under half of the plain text, `handlePaste` pastes the plain text. The fallback is gated on `<details>` so that a source whose plain text is Markdown (`[label](url)` has more letters than `label`) keeps its rich HTML.
- **Plain text:** a whitespace-only line would become an empty paragraph, so `transformPastedText` empties it first.
- **Failure:** `transformPastedHTML` wraps the cleanup in a `try`, so a bug in it degrades to the old behavior instead of blocking the paste.

## Images that are not on the site yet

A screenshot or an image file on the clipboard arrives as `clipboardData.files`, with no HTML. Word puts its images in the HTML as `data:` URLs, and RTFD-backed pastes can use `blob:` URLs. The editor reads the bytes and posts them to the `uploadPastedImages` handler. Clipboard files go without a token and are inserted at the cursor when uploaded. Images already in the document go with a token, and `window.resolvePastedImage(token, url, mediaId)` swaps the uploaded URL in. `PostEditorView.handlePastedImages` runs through the same `dropTask` queue and `uploadImages` loop as a Finder drop, so the pill and the toast behave the same. The file extension comes from the image's bytes, because Word labels its JPEGs `image/png` and WordPress refuses an upload whose extension disagrees with its contents. Without a connected site, the images stay as `data:` URLs and a toast says why.

Swift releases every token when it is done with it, whatever the outcome: success, a failed upload, no credentials, a temp-file write failure, and entries `PastedImage.decode` rejects. `PastedImage.forgetScript(_:)` builds one call to `window.forgetPastedImage` per token. Without the release, the editor treats an image with a live token as still in flight, so pasting the same image again after a failure would never retry it and it would stay base64. `resolvePastedImage` dispatches its swap with `addToHistory: false`, so the swap is not its own undo step: one ⌘Z after an upload takes back the whole paste, and ⌘⇧Z brings back the uploaded URL rather than the base64.

## Verifying a change here

`./test.sh` covers the corpus in jsdom. For a change that could depend on WebKit, re-run the real-WebKit harness described in `Scripts/fixtures/paste/README.md`. It puts a clipboard on the system pasteboard, pastes with a native `paste:` into the bundled `editor.html`, and checks the save with WordPress's validator.
